run.sh

A Makefile replacement written in pure bash.

curl -fsSL https://raw.githubusercontent.com/imgproxy/run.sh/main/run -o run && chmod +x run
  • It's bash, all the way down.
  • No runtime dependency, no build step, no framework.
  • run is a single file you download once and keep; your task logic lives in bin/, entirely yours to edit.
  • Project-wide helpers and variables go in .runrc (optional).
  • Compose tasks with run::depends_on task1 task2.
  • Optional ./run install-global adds a shell function that finds your project run in the parent subdirectory.

A task looks like this

#!/usr/bin/env bash
# bin/greet.sh — sourced by ./run, not executed directly.

description() { echo "Greet someone"; }

help() {
  cat <<'EOF'
Usage: ./run greet <name>
EOF
}

main() {
  echo "Hello, ${1:?name required}!"
}

Usage

./run              # list available tasks
./run <task> [args...]

Demo

Dependencies

Compose tasks with run::depends_on inside a task's main(). It runs each named task in order and stops at the first failure. 

main() {
  run::depends_on build test
  echo "deploying..."
}

Helpers and input

Built-in helpers available in all tasks: 

run::require_tool docker "docker is required"
run::require_arg --env "$env"
run::depends_on build test

# Interactive input
if run::prompt cyan "Deploy to production?" "y/N"; then
  env=$(run::user_input cyan "Environment")
  echo "Deploying to $env..."
fi

run::prompt takes a color, a question, and an optional choices string (default y/n), and resolves on a single keypress — no Enter needed. Capitalize a letter to make it the default, selected by pressing Enter. run::user_input reads a free-form value. Other helpers: run::require_tool, run::require_arg, run::color_echo, NO_COLOR env var, run::icon (skip/success/error/info/warning glyphs: ◇ ✓ ✕ ◆ ■), and run::msg_ok/run::msg_skip/run::msg_info/run::msg_warn/run::msg_err for ready-made colored status lines built on top of run::icon.
